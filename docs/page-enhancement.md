# Melhoria protegida de páginas

No editor, **Melhorar com IA** permite escolher todas as páginas ou marcar somente as páginas desejadas. A modal cabe no viewport sem rolagem vertical: a seleção extensa usa páginas de três opções, a galeria tem navegação lateral e o histórico abre em uma camada própria. Cada resultado pode ser comparado por inteiro com o original, ampliado e baixado; a altura das imagens se ajusta ao espaço disponível. A escolha do que gerar é independente da página aberta para conferência. O modelo é escolhido automaticamente no servidor; nome do provedor, modelo interno e custos não aparecem para o cliente. A nova versão nunca altera o canvas editável original.

Configure a chave do provedor no ambiente do servidor e reinicie. A chave, o catálogo de modelos e os dados de uso ficam restritos ao servidor. Modelos permitidos: `openai/gpt-image-2.5-sunburst` e `openai/gpt-image-2.5-flare`; o servidor prioriza o primeiro modelo disponível. A interface do cliente não oferece seleção de modelo nem exibe custos.

O padrão é **Redesign completo**, qualidade alta, pipeline `retail-layout-v11`. Antes da chamada paga, o editor mantém a quantidade, ordem e células exatas do grid original, e prepara uma camada comercial com títulos sem abreviação, condições, fotos originais e preços exatos, nas coordenadas dos objetos Fabric. Fotos, recortes, selos, marcas e logo vêm dos assets existentes; textos vêm dos objetos Fabric, sem OCR ou transcrição por IA. Etiquetas com condições adicionais mantêm seu conteúdo completo. O editor original não é alterado.

A IA recebe a imagem original completa como referência de edição e é instruída a melhorar o design da página inteira sem alterar produtos, grid ou dados comerciais. A guia com o grid exato fica no sistema para validação e idempotência, sem ser enviada ao modelo. A API recebe a proporção original quando suportada (por exemplo, 9:16 para Story). O resultado do redesign usa diretamente a imagem completa editada pela API. A camada comercial extraída do Fabric serve para conferir a quantidade e as coordenadas de origem antes da chamada, mas não é sobreposta à resposta: essa sobreposição duplicava textos, preços e molduras. O prompt exige a mesma quantidade e posição dos produtos; a prévia deve ser conferida antes da exportação porque modelos de imagem podem alterar detalhes comerciais. Páginas achatadas ou cards sem foto/nome/preço separados são recusados antes da cobrança; Acabamento leve continua disponível.

Resultados antigos permanecem no histórico e podem ser baixados. Uma versão anterior do redesign não satisfaz o lote novo nem é reutilizada como se tivesse recebido a nova montagem. O recibo e a chave de idempotência incluem a versão e a guia; clientes antigos devem atualizar antes de iniciar o novo redesign.

No modo **Acabamento leve** (compatibilidade com a primeira versão), o editor exporta uma cópia offscreen (até 2048 px no maior lado) e uma máscara binária. Fotos de produtos, cards, textos, logos e imagens não explicitamente classificadas como fundos são protegidos. A composição Sharp substitui integralmente os pixels protegidos pelos pixels originais, inclusive alpha. A IA atua apenas no acabamento das áreas decorativas livres. Arte inteiramente achatada/protegida é recusada antes da geração; páginas com vários frames exigem separação em páginas.

`POST /api/page-enhancements` verifica usuário/projeto/página, imagens e limites; salva original, máscara e recibo, retorna processing e registra a execução no ciclo do servidor Nitro. A chamada paga usa POST https://openrouter.ai/api/v1/images, a página original completa no redesign ou original e máscara no acabamento leve, n=1, PNG, qualidade escolhida e timeout de 300s. Prompt completo: server/utils/page-enhancement.ts. Não usa LLM de texto separado.

Armazenamento: `projects/{user}/{project}/enhancements/{hash}/`. O hash inclui versão do pipeline, intensidade, camada comercial, página, modelo, qualidade, original e máscara. Recibos e PNGs sobrevivem ao fechamento da janela. Advisory lock PostgreSQL por usuário impede duplicidade entre instâncias. Ledger privado limita cada conta a 20 tentativas/dia (UTC), uma geração simultânea. Não é um teto monetário: cobrança final depende dos tokens. As páginas escolhidas têm o original verificado antes da primeira geração paga e são processadas em sequência; o lote pode ser pausado após a página atual. Resultados atuais são reutilizados e uma interrupção incerta não é reenviada automaticamente.

`usage.cost` do provedor é guardado antes da composição. Ausência de custo permanece null, nunca zero. O orçamento das páginas restantes é uma projeção baseada nas chamadas já concluídas, não preço garantido. Rejeições explícitas 4xx sem geração têm custo zero; erros 5xx/timeouts são incertos. Falha ao persistir depois de chamar o provedor exige reconciliação manual; o original e arquivos já escritos permanecem preservados.

Para exportar o encarte completo, o SHA-256 do PNG atual de cada página é comparado com o recibo: edição posterior exige nova geração, que pode ser iniciada pelo lote direto. A interface também oferece PDF e ZIP das páginas já prontas, na ordem do projeto, mesmo quando outras páginas ainda não foram melhoradas. Resultados são PNGs achatados; elementos editáveis continuam no projeto original. A prévia deve ser conferida pelo usuário antes da exportação.

Validação: testes de máscara/render e composição RGBA, autorização e PNG; typecheck; build; smoke autenticado de configuração/histórico e revisão no navegador.
